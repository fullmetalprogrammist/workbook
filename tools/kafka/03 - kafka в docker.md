# Listeners

- Через лисенеры мы задаем адрес и порт, по которым будет доступен брокер
  - Адреса задаются через 0.0.0.0 - см дальше почему
  - Для брокера можно описать несколько лисенеров
    - Основная причина описать несколько лисенеров - это необходимость организовать доступ к брокеру из разных сетей
      - Например, для доступа с локального компьютера - один лисенер, а для доступа изнутри сети самого докера - другой лисенер
- Лисенеры описываются в параметре `KAFKA_LISTENERS`
- Какая связь между `KAFKA_LISTENERS` и `KAFKA_ADVERTISED_LISTENERS`?
  - лисенеры концептуально это интерфейсы для "внутреннего" взаимодействия брокеров внутри кластера
    - клиенты кафки о них ничего знать не должны напрямую, потому что некоторые лисенеры нужны исключительно для внутренних целей
  - поэтому, чтобы клиенты могли присоединиться к брокерам уже непосредственно для работы, нужны адвертайзы - через адвертайзы мы как бы раскрываем клиентам нужные лисенеры
  - После рукопожатия соединение закрывается и для работы открывается новое, и в нем уже используются адреса из адвертайзов
  - каждый адвертайз может быть связан только с одним лисенером
    - для лисенеров, которые не надо "раскрывать", адвертайзы не надо писать
- Объяснение на примере:

```yaml
kafka:
  ports:
    - "9093:9093"
  environment:
    KAFKA_LISTENERS: PLAINTEXT://0.0.0.0:9092,PLAINTEXT_HOST://0.0.0.0:9093
    KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://kafka:9092,PLAINTEXT_HOST://localhost:9093
    
kafka-ui:
  environment:
    KAFKA_CLUSTERS_0_BOOTSTRAPSERVERS: kafka:9092
```

- Нам надо работать с кафкой из двух сетей
  - Во внутренней сети докера
    - Для kafka-ui, видно что используется имя сервиса и порт kafka:9092
  - С локального компа
    - Потому что бизнесовый микросервис я запускал из IDE
      - Поэтому порт прокинут "9093:9093"
        - Т.о. при рукопожатии мой клиент кафки получает два адвертайза PLAINTEXT://kafka:9092,PLAINTEXT_HOST://localhost:9093
          - По первому он соединиться не сможет, потому что kafka для него ничего не значит, т.к. это имя сервиса внутри докера, а вот по localhost:9093 сможет, потому что порт 9093 локалхоста ведет на kafka:9093 и это объявленный лисенер 0.0.0.0:9093

## 0.0.0.0

- `0.0.0.0:9092` - здесь 0000 это специальное значение, которое означает "слушать порт 9092 с любым адресом"
  - На практике это означает, что запрос на `127.0.0.1:9092` или на реальный ip `172.18.0.2:9092` обработается, т.е. 0000 это как бы универсальный адрес для текущего компа \ сервиса
  - Для кафки в докере в данном случае использование 0000 единственный правильный вариант, потому что из-за особенностей последовательности запуска процесса сервиса (кафка в данном случае), настройки сети докера, разрешения адреса по имени сервиса все может перепутаться и адрес получится кривой, если использовать имя сервиса. А 0000 дает эффект, что какой бы адрес сервис не получил, запрос на этот адрес с портом 9092 обработается нормально.
