## Зачем обертки

- Находятся в java.lang https://docs.oracle.com/en/java/javase/26/docs/api/java.base/java/lang/package-summary.html
- Хранят разные статические утилитарные методы для своего примитивного типа
- Используются в дженериках



# autoboxing и unboxing

- `autoboxing` - это упаковка примитива в его обертку
- `unboxing` - это извлечение примитива из обертки
- и то, и другое происходит во время компиляции, в соответствующих местах компилятор автоматически добавляет нужные преобразования
  - По сути это срабатывает когда примитив присваивается туда где нужен объект, и когда объект присваивается туда где нужен примитив

```java
// autoboxing  int -> Integer
Integer x = 10;
List<Integer> numbers = List.of(10, 20, 30);

// unboxing  Integer -> int
int y = x;
int num = numbers.get(0);
```

- Б \ А - это синтаксический сахар над

```java
Integer.valueOf(10);
int y = x.intValue();
// и прочими подобными конструкциями
```



# Обертки, боксинг и коллекции

- Коллекции появились раньше дженериков
- В них все хранилось в виде Object
- За счет оберток и боксинга можно было делать например вот так:

```java
coll.add("Hello");
coll.add(person);
coll.add(5);  // <-- 5 боксится в Integer
```

- Правда при извлечении приводить к нужному типу в таком случае приходилось бы явно, т.к. все хранится как Object и компилятор не знает, чего мы понадобавляли.

# Стирание типов

- `type erasure` ("стирание" типов) - это базовый механизм работы дженериков
- после компиляции никаких дженериков не существует, они как бы "стираются"
- стирание - это механизм замены типа дженерика на реальный тип
  - на какой именно? по верхней доступной границе

Код с дженериками:

```java
// классы для примеров
class Animal { }
class Tiger extends Animal { }
```

```java
class Box<T> {  // <-- Вводим дженерик-тип T
    private T value;  // <-- И используем его в классе вместо "реального" типа тут

    public void set(T value) {  // <-- и тут
        this.value = value;
    }

    public T get() {  // <-- и тут
        return value;
    }
}

var box = new Box<Tiger>();  // <-- Закрываем дженерик конкретным типом
Tiger tiger = box.get();  // <-- Руками ничего приводить не приходится
```

После компиляции код с дженериками превращается в обычный код без дженериков. В нужных местах компилятор просто расставляет приведение к нужным типам:

```java
class Box {  // <-- Никакого T после компиляции нет.
    // У T в объявлении не было ограничений, поэтому он 
    private Object value;  // заменился по верхней границе (на Object, а не на Animal).

    public void set(Object value) {  // <-- Везде, где был T,
        this.value = value;
    }

    public Object get() {  // <-- произошла замена на реальный тип, Object в данном случае
        return value;
    }
}

Box box = new Box();  // <-- Никаких дженериков нет
Tiger tiger = (Tiger) box.get();  // <-- Компилятор подставил приведение к нужному типу
```

Если дженерик ограничен:

```java
class Box<T extends Animal> {  // <-- Указано, что T это подтип Animal
    private T value;
    public void set(T value) {...}
    public T get() { return value; }
}

var box = new Box<Tiger>();  // <-- Желаемый тип - Tiger
Tiger tiger = box.get();
```

```java
class Box {
    private Animal value;  // <-- T везде заменился
    public void set(Animal value) {...}
    public Animal get() { return value; }  // <-- по типу-ограничителю
}

Box box = new Box();  // <-- Дженериков нет
Tiger tiger = (Tiger) box.get();  // <-- Компилятор знает, что мы хотели Tiger для Box
// Tiger без проблем ложится в Animal внутри Box
```



## Почему в дженериках нельзя использовать примитивы

- В дженериках нельзя использовать примитивы:

```java
List<int> numbers = List.of(10, 20, 30);  ❌
List<Integer> numbers = List.of(10, 20, 30);  ✅
```

- Это из-за стирания типов. Механика стирания типов работает только с объектами, а не с примитивами. Вместо int-дженерика в качестве реального типа невозможно поставить Object, потому что int не является наследником Object. Следовательно, чтобы стирание работало, нужен объектный тип, поэтому используется Integer.
