## Строка - это объект, причем иммутабельный

- Строка - это объект, внутри которого находится массив символов.
  - В массиве в современной джаве лежат байты `byte[]`, а не непосредственно символы.
- Строки в джаве иммутабельные, поэтому абсолютно любое "изменение" по сути порождает новую строку

```java
String mes = "hello";
mes = mes + " world";  // В mes записалась новая строка "hello world", исходный "hello" не изменился
mes = mes.toUpperCase();  // В up записалась новая строка "HELLO WORLD", а "hello world" не изменилась
```



## Сравнение строк через == и .equals()

- Поскольку строки это объекты, их надо сравнивать через equals, а не через ==
  - Потому что через == сравнятся ссылки, а через equals - контент
  - Плюс из-за пула строк может возникнуть путаница, поэтому equals - это жбшечка, а == - это рулетка

```java
String a = "Hello";
String b = "Hello";
String c = new String("Hello");
if (a.equals(b))  ✅  // true, тк в обоих переменных слово Hello
if (a == b)       ❌  // тоже true, но лишь из-за механизма стринг пула, а не из-за одинаковых слов
    
if (a == c)           // false - обосрались, тк сравниваются ссылки, а не слова
if (a.equals(c))      // true - все корректно, сравнивается текст
```



## Замена выражений при компиляции

```java
String message = "hello" + " " + "world";
```

Когда компилятор может понять итоговое значение, как в данном случае, в байткоде окажется готовая строка "hello world" вместо выражения `"hello" + " " + "world"`, т.е. конкатенации в рантайме не будет.

---

```java
final String world = "world";
String message = "hello" + " " + world;
```

Здесь тоже вместо `"hello" + " " + world` будет "hello world" без конкатенации в рантайме, потому что компилятору за счет final + присваивания гарантированно известно значение world при компиляции, значит он может вычислить выражение и заменить его на готовую строку.

---

```java
String world = "world";
String message = "hello" + " " + world;
```

А вот тут компилятор не сможет заменить `"hello" + " " + world` на готовую строку, потому что world это обычная переменная, без final, и компилятор не знает ее значение при компиляции.



## String pool

### Зачем нужен пул

- Пул строк хранит ссылки на строки и в некоторых случаях JVM может искать строки в пуле и повторно их использовать. Т.о. экономится память и снижается нагрузка на сборщик мусора.

### Какие строки попадают в пул

- Какие строки попадают в пул
  - В пул попадают все литералы
  - Все строки, на которых явно вызван метод `.intern()`

```java
String a = "hello world";
String message = someString.intern();
```

### Интернирование, метод .intern()

- "Интернирование" значит "Проверить, есть ли строка в пуле. Если есть, вернуть ссылку на нее. Если нет, поместить строку в пул и вернуть ссылку".
  - Этим занимается jvm.
- При вызове intern() мы явно запускаем интернирование.



## Создание строк через new и через литерал

Вопрос - сколько строк создается в этом коде?

```java
String a = new String("Hello");
```

Ответ: две. Первая строка это литерал "Hello". Она передается в конструктор new String и получается вторая строка. Ссылка на нее сохраняется в переменную `a`, а первую строку "Hello" в памяти удерживает пул строк.

- При использовании new всегда создается новая строка в куче.
- При использовании литерала проводится интернирование.



## Примеры для самоконтроля

```java
// Пример 1
String a = "java";
String b = "java";
String c = new String("java");

a == b;
a == c;
a.equals(c);
```

```java
// Пример 2
String a = new String("hello");
String b = a.intern();
String c = "hello";

a == c;
b == c;
```

```java
// Пример 3
final String part = "ja";
String a = part + "va";

String dynamic = args.len > 0 ? "ja" : "ja";
String b = dynamic + "va";

a == "java";
b == "java";
```

### Ответ 1

- `a == b : true`, литерал "java" помещается в пул строк, ссылка кладется в а. В b кладется ссылка на эту же строку, потому что опять используется литерал "java", стало быть сначала проверяется пул, а там "java" уже есть. == сравнивает ссылки. Ссылки равны, поэтому true.
- `a == c : false`, потому что new String всегда создает новый объект в куче. Объекты разные, ссылки разные, == дает false.
- `a.equals(c) : true`, потому что equals сравнивает текст строк.

### Ответ 2

- `a == c : false`, потому что new String создает новый объект, ссылки разные, == дает false.
- `b == c : true`, в a хранится "hello". Вызов a.intern() приводит к интернированию "hello" и в b оказывается ссылка на "hello" из пула. В c тоже возвращается ссылка на "hello" из пула. Ссылки одинаковые, == дает true.

### Ответ 3

- `a == java : true`. В пуле окажется "ja" и "java" ("va" вообще есть только в исходном коде, но после компиляции его нет, потому что "ja" + "va" заменятся на "java", так что "va" и в пуле тоже не будет). В `а` будет ссылка на "java", вместо литерала "java" - ссылка на строку "java", ссылки одинаковые, == дает true.
- `b == "java" : false`. Из-за того что dynamic вычислится в рантайме, то и b вычислится в рантайме через конкатенацию. Поиска в пуле не будет, получится новая строка при конкатенации. "java" возьмет ссылку из пула, ссылка с b разная, == даст false.
